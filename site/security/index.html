Security

Folkweb runs on every page you visit, so a bug in Folkweb would be a bug on every site. Security comes before features.

How Folkweb is built

  • Minimal permissions. Storage and a right-click menu only. Access to a site’s files is requested from you, per site, only when you check an image.
  • No remote code. Everything that runs ships inside the extension. No eval, no remote scripts, a strict content security policy.
  • Pages are treated as hostile. Folkweb only writes text into pages, never HTML, and ignores messages from pages.
  • Lists are data, not code. Filter lists use a safe subset of the uBlock Origin syntax. Anything that could run code or load resources is rejected.
  • Safe networking. Every request goes through one checked function: no cookies, size and time limits, and no access to local or private addresses.
  • Supply chain. Exactly pinned dependencies, install scripts disabled, CI actions pinned to commits, and a security scan on every change.

Report a vulnerability

Please email security@folkweb.org. Don’t open a public issue. Include what you found, how to reproduce it, and the browser and Folkweb version. We aim to reply within 7 days, keep you updated, and credit you if you wish.

Good-faith research is welcome: test only with your own data and accounts, don’t harm users or degrade the service, and give us reasonable time to fix before disclosure. We won’t pursue legal action against research that follows these rules.
